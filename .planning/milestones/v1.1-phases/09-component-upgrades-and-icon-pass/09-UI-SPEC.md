## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap (e.g. `gap-1` between icon and heading text) |
| sm | 8px | Compact element spacing, badge padding |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, grid gap |
| xl | 32px | Layout column gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level vertical spacing |

Exceptions:
- Icon touch targets on icon-only buttons: minimum 44px (accessibility). Use `p-3` (12px) padding on a 24px icon to reach 48px total, exceeding the 44px minimum.
- Skeleton shimmer rows within a card: 8px vertical gap between skeleton lines (`space-y-2`).

## Color

All color values are OKLCH. The project runs permanently in dark mode.

| Role | OKLCH Value | CSS Variable | Usage |
|------|-------------|-------------|-------|
| Dominant (60%) | oklch(0.10 0.01 250) | `--background` | Page background, all views |
| Secondary (30%) | oklch(0.14 0.01 250) | `--card` | Cards, sidebar, panels, dialogs |
| Muted surface | oklch(0.16–0.18 0.01 250) | `--secondary` / `--muted` | Hover states, skeleton base |
| Primary / Cyan accent (10%) | oklch(0.75 0.18 195) | `--primary` | Neon cyan — see reserved list |
| Magenta accent | oklch(0.70 0.25 330) | `--accent` | Neon magenta — see reserved list |
| Destructive | oklch(0.65 0.22 25) | `--destructive` | Destructive badge state, error badges |
| Amber / Stale | oklch(0.75 0.15 85) | (no CSS var — use OKLCH arbitrary) | Stale node status badge, pending instance badge |
| Border | oklch(0.75 0.18 195 / 15%) | `--border` | Card borders, separator lines |
| Muted foreground | oklch(0.60 0.04 195) | `--muted-foreground` | System/finished state badges, placeholder text |

### Cyan (`--primary`) reserved for:
- Node status badge: Connected state (background + text + border + shadow)
- Instance status badge: Running state (background + text + border + shadow)
- Audit event badge: Command category
- Scroll-to-bottom FAB button background
- Section heading icon color (`text-primary`)
- Execute action button icon + border
- `glow-cyan` hover/focus glow on interactive buttons
- Focus rings (`--ring`)

### Magenta (`--accent`) reserved for:
- Node status badge: no direct use (amber covers stale, magenta is for interactive/accent)
- Audit event badge: Auth category
- `glow-magenta` hover/focus glow on voice-related elements
- VoiceButton active recording indicator (Phase 10 — do not implement here)

### Amber reserved for:
- Node status badge: Stale state
- Instance status badge: Pending state
- `glow-amber` hover/focus glow (new utility to add in this phase)

### Destructive reserved for:
- Node status badge: Disconnected state
- Instance status badge: Errored state
- Audit event badge: Error category
- `glow-red` hover/focus glow (new utility to add in this phase)

### Badge glow rule:
Status badges use always-on inline `box-shadow` with OKLCH arbitrary values — NOT the `.glow-*` hover utilities. Example for cyan badge: `shadow-[0_0_6px_1px_oklch(0.75_0.18_195/40%)]`. The `.glow-*` utilities are for interactive buttons (hover-triggered only).

## Loading Skeleton Contract

Three plain-text loading states to replace. Shape each skeleton to match the content grid below.

### NodeGrid Skeleton
3-card grid layout, each card has 3 skeleton rows:
```
grid grid-cols-1 md:grid-cols-2 xl:grid-cols-3 gap-4 p-6
  └─ card (border border-border rounded-lg p-4 space-y-2)
       ├─ Skeleton h-5 w-3/4   (node name)
       ├─ Skeleton h-4 w-1/2   (status badge placeholder)
       └─ Skeleton h-4 w-2/3   (metadata line)
```
Render 3 skeleton cards minimum.

### InstanceList Skeleton
Single-column list, each row has 3 skeleton lines:
```
space-y-3 p-4
  └─ row (border border-border rounded-lg p-3 space-y-1)
       ├─ Skeleton h-4 w-2/3   (instance ID)
       ├─ Skeleton h-3 w-1/3   (state badge placeholder)
       └─ Skeleton h-3 w-1/2   (timestamp)
```
Render 4 skeleton rows minimum.

### $nodeId.tsx Route Skeleton (line 75 replacement)

```
p-6 space-y-4
```

## Glow Utility Contract

### Existing (from Phase 8 — do not modify)
- `.glow-cyan` — hover/focus only, `oklch(0.75 0.18 195 / 60%)`, 8px spread
- `.glow-magenta` — hover/focus only, `oklch(0.70 0.25 330 / 60%)`, 8px spread

### New (add to `@layer utilities` in index.css this phase)
- `.glow-amber` — hover/focus only, `oklch(0.75 0.15 85 / 60%)`, 8px spread — same pseudo-element pattern as existing utilities
- `.glow-red` — hover/focus only, `oklch(0.65 0.22 25 / 60%)`, 8px spread — same pseudo-element pattern

These new utilities follow the exact CSS pattern already established (pseudo-element opacity animation, `z-index: -1`, `isolation: isolate`). Never animate `box-shadow` directly (STATE.md pitfall).

### Usage rule
`.glow-*` utilities apply to: interactive buttons and controls (hover/focus triggered).
Status badges use inline `shadow-[...]` Tailwind arbitrary values (always-on, not hover-triggered).

## Anti-Patterns (Enforced)

- Never use raw Tailwind semantic color classes (`bg-green-600`, `bg-blue-500`, `bg-yellow-500`) for status badges — use OKLCH arbitrary values
- Never add icons to `@theme inline` block — only `:root` / `.dark` raw CSS blocks
- Never animate `box-shadow` directly — pseudo-element opacity animation only (existing glow pattern)
- Never add mount animations to stream output rows — causes animation queuing at >5 events/sec
- Never import from `lucide-react` directly in hand-authored component files — use `@/lib/icons`
- Never migrate shadcn-generated files to icons.ts (select.tsx, dialog.tsx, etc.) — they may be overwritten
- After `npx shadcn add dialog`, always restore `glow-cyan` in button.tsx default variant
