### Known Issue: Hard-Reload Auth Guard Race

**Severity:** Medium (pre-existing, not introduced by v1.2)

When a user hard-reloads to `/dashboard/audit` or `/dashboard/onboarding`, the `beforeLoad` guard in `route.tsx` checks `getAccessToken()` synchronously. The module-level `refreshAccessToken()` call in `api.ts` is async and hasn't resolved yet — so the guard sees `null` and redirects to `/login`. Once logged in, all routes work correctly including WS reconnect.

This does NOT affect normal navigation (clicking links) or tab restore (the proactive timer handles it). It only affects hard browser refreshes and direct URL entry.

**Recommendation:** Address in a future milestone by making `beforeLoad` await the module-level refresh promise, or by checking localStorage for a refresh token as a "probably authenticated" fast-path.
