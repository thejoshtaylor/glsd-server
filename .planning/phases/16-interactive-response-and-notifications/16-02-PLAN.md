**InteractiveResponseUI.tsx** — Create new component (~120-180 lines):

```typescript
interface InteractiveResponseUIProps {
  instanceId: string
  nodeId: string
}
```

**Component logic:**

1. **State selectors from wsStore:**
   - `instanceStatus = useWsStore(s => s.instanceStatuses[instanceId])`
   - `promptState = useWsStore(s => s.promptStates[instanceId])`
   - `events = useWsStore(s => s.streamBuffers[instanceId] ?? [])`
   - `socket = useWsStore(s => s.socket)`

2. **Local state:**
   - `selectedOptions: Set<string>` (for single/multi select tracking)
   - `freeformText: string` (for freeform input)
   - `submitting: boolean` (loading state during claim + dispatch)

3. **CRITICAL nil-guard (STATE.md locked):** FIRST check before any other logic:
   ```typescript
   if (!instanceStatus || instanceStatus === 'finished' || instanceStatus === 'errored') return null
   if (promptState === 'answered') return null
   ```

4. **Find the last AskUserQuestion or detect freeform_wait:**
   - Reverse-iterate `events` to find the last event where `event.type === 'tool_use' && event.name === 'AskUserQuestion'`.
   - Check if the last stream_event had `gsd === 'freeform_wait'` — but since gsd is on the WS envelope (not in the NdjsonEvent stored in streamBuffers), detect freeform by checking `promptState === 'pending'` and no AskUserQuestion found. The freeform_wait classification is stubbed in the classifier (see RESEARCH.md Open Questions), so in practice this branch won't render until the classifier is enabled. Wire it anyway for future use.
   - If no AskUserQuestion found AND promptState is not 'pending', return null.

5. **Parse AskUserQuestion input:**
   ```typescript
   const askInput = askEvent?.input as {
     questions: Array<{
       question: string
       header: string
       multiSelect: boolean
       options: Array<{ label: string; description: string }>
     }>
   } | undefined
   const question = askInput?.questions?.[0]  // Typically 1 question
   ```

6. **Submit handler (`handleSubmit`):**
   - Set `submitting = true`.
   - Send `claim_prompt` via WS: `socket.send(JSON.stringify({ type: 'claim_prompt', instance_id: instanceId }))`.
   - Wait briefly (the `prompt_claimed` message will update `promptState` in wsStore). Use a small timeout or optimistic approach: proceed immediately since the broadcast will update state.
   - Fetch session_id: `const instance = await api<InstanceResponse>('/api/instances/' + instanceId)`. If `instance.session_id` is null, show error toast and return.
   - Format the prompt string: for single-select, use the selected option label; for multi-select, join selected labels with `", "`; for freeform, use the text.
   - Send `submit_answer` via WS: `socket.send(JSON.stringify({ type: 'submit_answer', instance_id: instanceId, prompt: formattedPrompt, session_id: instance.session_id }))`.
   - Set `submitting = false`.

   Wrap in try/catch — on error, set submitting false and show error via `console.error`.

7. **Render — three modes:**

   **Mode A: AskUserQuestion with multiSelect=false (RESP-01):**
   - Render `question.question` as header text.
   - Render each `option` as a button with cyberpunk styling:
     - `bg-card hover:bg-primary/10 border border-border hover:border-primary/50 rounded-lg p-3 text-left transition-colors`
     - Selected state: `border-primary bg-primary/10`
     - Option label in `font-medium text-foreground`, description in `text-sm text-muted-foreground`
   - Single-click selects AND submits (since single-select, clicking an option immediately triggers handleSubmit with that option).
   - Alternatively: click to select, then click a Submit button. Use the click-to-select-then-submit approach for consistency with multi-select.

   **Mode B: AskUserQuestion with multiSelect=true (RESP-02):**
   - Same header rendering.
   - Each option renders as a toggleable card (checkbox style): clicking toggles membership in `selectedOptions` Set.
   - Show a "Submit" button below the options that calls handleSubmit with all selected options joined.
   - Checked state: `border-primary bg-primary/10` with a checkmark icon.

   **Mode C: Freeform wait (RESP-03):**
   - Render a text prompt: "This instance is waiting for your input."
   - Render a `<textarea>` with `bg-card border border-border rounded-lg p-3 text-foreground` styling, placeholder "Type your response...".
   - Render a Submit button that calls handleSubmit with `freeformText`.

8. **Disabled states:**
   - If `promptState === 'claimed_by_other'`: render all controls disabled with message "Another tab is responding to this prompt".
   - If `submitting`: show loading indicator on submit button, disable all controls.

9. **Wrapper styling:** The entire component wraps in a `div` with:
   `border-t border-border bg-card/30 p-4 space-y-3`
   — this sits below the stream events list in StreamPanel.

10. **No motion library** — use `tw-animate-css` classes only. A simple `animate-in fade-in duration-200` on the wrapper is acceptable. Do NOT use `framer-motion` or the `motion` package.
