```typescript
const executeMutation = useMutation({
  mutationFn: async () => {
    const result = await api<{ instance_id: string }>('/api/execute', {
      method: 'POST',
      body: JSON.stringify({
        node_id: node.node_id, project, work_dir: projectMap[project] ?? project,
        prompt, session_id: sessionId || null,
      }),
    })
    return result
  },
  onSuccess: (data) => {
    setPendingInstanceId(data.instance_id)
    if (socket && socket.readyState === WebSocket.OPEN) {
      const msg: WsOutgoingMessage = { type: 'subscribe', instance_id: data.instance_id }
      socket.send(JSON.stringify(msg))
    }
    onInstanceCreated(data.instance_id)
    queryClient.invalidateQueries({ queryKey: ['instances'] })
  },
})
```

Component structure:
1. **State:** `selectedCommandId: string | null`, `paramValues: Record<string, string>`, `paletteOpen: boolean` (default true)
2. **Project resolution:** Use the same `useQuery(['projects', node.node_id])` pattern as ExecuteForm to get `projectsQuery`. Derive `currentProject` from first available project name, and `workDir` from `projectMap[currentProject] ?? currentProject`. Show an informational message if no project is selected.
3. **Dispatch mutation:** Same pattern as ExecuteForm's `executeMutation`:
   - POST to `/api/execute` with `{ node_id: node.node_id, project: currentProject, work_dir: workDir, prompt: expandedPrompt, session_id: null }`
   - On success: subscribe to instance via WS, call `onInstanceCreated(data.instance_id)`, reset `selectedCommandId` and `paramValues`
   - Track `pendingInstanceId` for button disable state (same pattern as ExecuteForm)
4. **canDispatch guard:** `currentProject && node.status === 'connected' && (!selectedCommand.params.length || allRequiredParamsFilled)` — per Pitfall 4, NEVER dispatch if required params are empty
5. **Layout:**
   - Collapsible `<details>` wrapper (same pattern as ExecuteForm's Advanced section), default open
   - Section heading: `<Command size={20} className="text-primary" />` + "GSD Commands" in uppercase tracking-widest muted-foreground (match ExecuteForm heading style)
   - Category tabs using inline buttons (one per category), active state highlighted with `bg-primary/10 text-primary`
   - Command list: Render commands filtered by active category as clickable rows
   - Each row: command label (bold), description below in muted text, `<Info>` icon with title attribute showing `whenToUse` text
   - When command is clicked: if no params, dispatch immediately. If has params, expand inline mini-form below the command row.
   - Mini-form: One `<Input>` per param with `label` and `placeholder`. Dispatch button below: `<Rocket size={14} /> Dispatch` — disabled when `!canDispatch` or mutation pending.
6. **Styling:** Match existing `bg-muted/50 rounded-lg border border-border p-4 space-y-3` pattern from ExecuteForm container.
