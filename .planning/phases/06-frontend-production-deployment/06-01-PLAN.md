  <action>
Create `frontend/Dockerfile` as a multi-stage build:

**Stage 1 — build:**
```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package.json package-lock.json* ./
RUN npm ci
COPY . .
RUN npm run build
```
- Uses `node:22-alpine` (LTS, small image)
- `npm ci` for deterministic installs
- `npm run build` runs `tsc -b && vite build`, output goes to `dist/` (Vite default)

**Stage 2 — serve:**
```dockerfile
FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
- Copies built assets from stage 1 into Nginx html root
- Copies custom nginx.conf as the default server config
- Exposes port 80

Create `frontend/nginx.conf` with these exact directives:

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    # Gzip compression for text assets
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml text/javascript image/svg+xml;
    gzip_min_length 256;

    # API proxy
    location /api/ {
        proxy_pass http://api:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket proxy
    location /ws/ {
        proxy_pass http://api:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    # SPA fallback — all other paths serve index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Key details:
- `proxy_pass http://api:8000` uses the Docker Compose service name `api` for DNS resolution
- WebSocket location includes `Upgrade` and `Connection` headers required for WS handshake
- `proxy_read_timeout 86400s` (24h) prevents Nginx from closing long-lived WebSocket connections
- `try_files $uri $uri/ /index.html` enables SPA client-side routing (TanStack Router)
- Gzip compression reduces transfer size for JS/CSS assets

  <action>
Update `docker-compose.yml` to add a `frontend` service. The final file should contain three services: `db`, `api`, and `frontend`.

Add this service definition after the `api` service:

```yaml
  frontend:
    build: ./frontend
    depends_on:
      - api
    ports:
      - "80:80"
```

Also update the `api` service to remove external port mapping since Nginx is now the entry point. Change:
```yaml
    ports:
      - "8000:8000"
```
to:
```yaml
    expose:
      - "8000"
```

This ensures:
- `api` port 8000 is accessible within the Docker network (for Nginx proxy) but NOT exposed to the host
- `frontend` port 80 is the only externally-exposed port
- `frontend` depends on `api` so the backend starts first
- Build context is `./frontend` which contains the multi-stage Dockerfile

Do NOT change the `db` service or the `volumes` section.
